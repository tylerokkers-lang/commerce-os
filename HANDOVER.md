## 1. What this is

An ecommerce operating system for one business selling through two independent
channels: a Shopify store and an Amazon UK seller account. It is the layer above
the storefronts — research, sourcing, compliance, pricing, fulfilment,
invoicing, VAT and cashflow — with automation that must ask before it spends
money.

It is a **new, standalone project**. It has no relationship to the other
projects in `/Users/tylerokkers/Desktop/claude/`, and in particular nothing to
do with `informax-site`, which is a live production marketing website.

## 3. Stack

Next.js 16.3.1 (App Router), React 19.2.8, TypeScript strict, Tailwind CSS v4,
Supabase, Vitest, PGlite for schema verification.

**This is Next.js 16.** `middleware.ts` is deprecated in favour of `proxy.ts`,
and `cookies()`, `headers()`, `params` and `searchParams` are async. Read
`node_modules/next/dist/docs/` before writing framework code. `AGENTS.md` says
the same thing and is regenerated by `next dev`.

## 5. Demo mode

Demo mode is the default and the system falls back to it whenever Supabase is
not fully configured. Live mode needs Supabase configured **and**
`COMMERCE_OS_MODE=live` set explicitly. This is deliberate: the system cannot
touch a real marketplace by accident.

Demo data lives in `src/lib/demo/dataset.ts` and runs through the real
profitability engine, so the figures are internally consistent rather than
painted on. It is seeded deterministically, so the numbers are stable across
refreshes. Every screen carries a banner while demo mode is on.

The demo catalogue deliberately includes a product blocked on Amazon for a real
policy reason, a loss-making product, and a supplier that fails Amazon's
seller-of-record requirement. A demo where everything is healthy teaches
nothing.

## 7. Deliberate decisions worth knowing

- **Money is integer pence.** Every column ends `_minor`. All arithmetic goes
  through `src/lib/core/money.ts`.
- **Contribution, not revenue, is the headline figure** on the dashboard.
- **Empty is not the same as unknown.** A live business with no orders shows
  zeros. Aggregates not yet implemented return honest empties rather than
  plausible numbers. Do not "fill these in" with estimates.
- **Compliance is a hard gate** and automation cannot override it.
- **Financial and audit records are never deleted.** Corrections are offsetting
  documents. The database enforces this with triggers.
- **`'use server'` modules may only export async functions.** Exporting a plain
  object from one does not fail loudly — it arrives as `undefined` on the
  client. Form state types live in a separate `state.ts` for this reason. This
  was a real bug, caught by running the page.

## 8. Things that will bite you

- `database.types.ts` is generated. Edit the migrations and run
  `npm run db:types`, never edit the file.
- The generator emits foreign keys as `Relationships`. Without them, Supabase
  types every nested select as `never`. If a `.select('*, table(col)')` starts
  returning `never`, regenerate.
- The dev server for this project is registered in the *informax-site*
  `.claude/launch.json` as `commerce-os-dev` on port 3102, because that is the
  primary working directory of the session that created it. There is also a
  local `.claude/launch.json` here for when this repo is opened directly.
